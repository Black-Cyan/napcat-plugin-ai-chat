# QQ 智能聊天机器人（napcat-plugin-ai-chat）

版本：`0.1.0`。一个 NapCat 插件，支持 OpenAI 兼容、Anthropic Messages 和 Google Gemini API，提供隔离会话、长期用户记忆、增量摘要、图片与表情包理解、所有者指令及认证 WebUI。

## 构建与安装

```bash
pnpm install
pnpm --dir src/webui install
pnpm run typecheck
pnpm test
pnpm run build
```

将 `dist/` 安装到 NapCat 插件目录。需要 NapCat `4.15.1` 或兼容版本，以及 Node.js 22 或更高版本。插件 ID 为 `napcat-plugin-ai-chat`。

后端及纯 JavaScript 依赖已打包进 `index.mjs`，SQLite 使用 Node 内置 `node:sqlite`，部署目录不需要额外安装 `node_modules`。

## 首次配置

打开 NapCat WebUI 中的 **AI 聊天控制台**：

1. 在“模型”中添加至少一套配置，填写模型、API 地址和密钥，并声明实际上下文上限、视觉、工具调用及结构化输出能力。
2. 将其中一套设为全局默认聊天模型。摘要、记忆提取和视觉任务可单独配置模型。
3. 在“行为与上下文”中设置所有者 QQ 号、参与意愿、批处理和上下文预算。
4. 按需调整全局提示词、会话覆盖、表情包和黑名单。

所有管理 API 都需要 NapCat WebUI 登录认证。API 密钥与数据库连接串只保存在本地配置中，读取时脱敏，不进入业务数据库或数据导出文件。

## 模型协议

- **OpenAI 兼容**：默认 `https://api.openai.com/v1`，使用 `/chat/completions`。
- **Anthropic**：默认 `https://api.anthropic.com`，使用 `/v1/messages`。
- **Google Gemini**：默认 `https://generativelanguage.googleapis.com/v1beta`，使用原生 `generateContent` 与 `streamGenerateContent?alt=sse`。API Key 仅通过 `x-goog-api-key` 请求头发送。
- **Gemini 模型发现**：填写 API Key 后，WebUI 通过官方 `GET /models` 分页获取模型，只展示支持 `generateContent` 的模型，并处理缓存、刷新失败和空列表。空选择使用 Google 返回顺序中的首个可用模型，已有不可用选择不会被静默替换。

自定义兼容服务填写对应协议根地址；官方 Google API 无需填写 Base URL，Gemini 的自定义端点仅位于高级设置。视觉关闭时不会把图片数据发送给该模型；不支持原生结构化输出时使用严格 JSON 解析与 schema 校验。模型列表未声明的视觉、工具调用和结构化输出能力仍需显式配置。

## 对话与记忆

- 私聊和每个群聊都有独立的原始消息、消息批次和增量摘要。
- 群聊可以在无需 @ 的情况下自然参与，也可以返回 `NO_REPLY`。默认参与意愿为 `0.7`。
- 默认批次：3 秒静默、15 秒最长等待、20 条消息上限。会话内部串行，跨会话默认最多 3 个任务。
- 原始消息永久保留。摘要只推进精确的消息覆盖位置，失败不会删除或跳过历史。
- 用户档案以 QQ 号为主键，增量记忆归属于该档案：**私聊记忆只用于私聊；群聊记忆可跨群及用于私聊。** 其他机器人也按参与者处理，本机器人不会反复触发自己。
- 同一来源刷屏可触发冷处理；机器人之间连续往返 3 轮会强制跳过一次，防止互相无限回复。

## 所有者私聊指令

指令前缀默认为 `#`，仅在已配置所有者的私聊中由确定性代码处理：

```text
#帮助
#运行模式 [黑名单|白名单]
#拉黑用户 <QQ>
#解除拉黑用户 <QQ>
#拉黑群 <群号>
#解除拉黑群 <群号>
#允许用户 <QQ>
#解除允许用户 <QQ>
#允许群 <群号>
#解除允许群 <群号>
#拉黑用户 <QQ> 删除
#拉黑群 <群号> 删除
#确认 <六位令牌>
#收藏表情        （先回复图片或商城表情）
#启用
#停用
```

拉黑在消息入库之前生效，既有数据默认冻结。带“删除”的操作还需要 60 秒内二次确认。不能拉黑最后一个所有者。

## 访问控制与黑白名单

插件提供全局的黑白名单控制：

- **运行模式**：
  - **白名单模式（新安装默认）**：只有加入当前生效白名单的用户（私聊）或群聊（整群）才被允许使用；若未选择生效白名单或名单为空，**默认全部禁用**。
  - **黑名单模式**：只有加入当前生效黑名单的用户或群聊被拦截；若未选择生效黑名单或名单为空，**默认全部允许**。
- **名单库管理**：支持创建多份命名黑名单和白名单。每种类型在同一时间最多指定一份为当前生效名单。名单支持重命名、复制副本、删除，并在删除生效白名单时给出警示。
- **联系人选择**：WebUI 实时从 NapCat 获取好友与群列表，支持关键词搜索、分类筛选、单选多选与批量加入，同时也允许手动输入任意 QQ 号或群号（自动去除前导零规范化）。
- **即时撤销**：名单变更在消息入库前、模型调用前、工具执行前、回复发送前均进行校验，被撤销权限的任务将立即中止。

## 数据库

默认使用插件数据目录中的 SQLite。WebUI 也支持 PostgreSQL 和 MySQL，提供连接测试、TLS 和连接池配置。

同一时间只启用一个后端。切换数据库不会自动迁移或同步数据；请先“备份与迁移 → 导出 JSON 数据”，再在新后端导入。数据库不可用时会暂停模型、记忆与工具处理，不会自动退回 SQLite。

## 表情包与媒体

模型可以理解和收藏图片/商城表情，记录摘要、标签、频率与使用统计，并按语境自主发送。没有固定收藏频率门槛，来源不限制传播范围。安全判断失败、图片下载失败或内容不确定时跳过。

媒体下载仅允许 HTTP(S) 图片，限制类型、大小、超时和重定向，并拒绝 loopback 与私有网络地址。已收藏表情保存为本地内容文件，发送时仍由当前会话工具代理校验。

## 安全边界

- 黑名单、所有者校验、记忆传播范围和工具目标全部由模型外代码执行。
- 自定义提示词不能扩大权限。聊天、昵称、图片文字和工具结果均视为不可信数据。
- 模型上下文不包含不必要的 QQ/群号、秘密或运行环境；发送前还有敏感内容精确匹配与路径/连接串检查。
- 工具只允许当前会话目标；撤回会验证消息属于本机器人；副作用通过幂等键避免恢复重放。
- 管理页面、原始历史和记忆只在认证 WebUI 中可见。日志不主动记录消息正文或密钥。

没有任何提示词可以数学意义上证明能抵抗所有注入。本插件将关键权限放在模型之外，并对输出做最后检查；上线前仍应使用自己的模型和群聊场景进行安全验收。

## 验证范围

Vitest 包含黑名单、记忆传播、摘要失败、消息去重、协议转换、媒体 URL 策略与回复格式测试。SQLite 合约测试默认运行；PostgreSQL/MySQL 需要用户提供测试实例后进行相同验收。真实 NapCat 收发、撤回、poke、收藏表情以及第三方模型调用需要测试账号与密钥，不应在无测试配置的开发环境中直接执行。
